## 二、这轮补齐了什么

| 事项 | 名称 | 影响 |

## 三、面试话术参考

**开场：**

> "MuSiQue-Ans 是一个公开冻结的多跳问答基准。我在 1000 段联合检索池、50 条冻结样本上，真实模型端到端 Recall@5 是 48.0%，95% CI [39.0, 57.0]。作答率 24%——另外的 76% 系统没有勉强答，而是门控明确拒答了。这正是 RAG 工程里最重要、也最常被掠过的一个决定。"

**弱点（高并发）时：**

> "scout 是单进程研究实现。高并发压测还没跑过。” 原项目里有意思的（异步入库 / 流式 / 降级）是以前的平台做的，它的预算管控目前在本地实现——生产上要放进 Redis 原子预扣加结算流水，并支持并发竞态。

**问到换模型的收益是不是一定有：**

> "我在 MuSiQue 上做过一遍对照：用哈希向量时 Recall@5 是 27.3%；把向量模型与重排模型
> 换成中文的 bge 系列之后——纯稠密通道反而降了 2.9pp。原因很直接：MuSiQue 是英文语料，
> 中文模型编码英文段落发挥不出语义优势。这条写进了报告，没有删——
> '向量模型必须匹配语料语言'不是口号，是有代价的常识。"

**问到为什么回答正确率还不够高时：**

> "MuSiQue 的 50 条冻结样本里，我答了 12 条、拒了 38 条，编造 0 条。
> 这不是 bug：幻觉率与误拒率是两个独立的指标——答得准也拒得稳的系统，
> 才真正值得信赖；一个从来不说'不知道'的系统，它的每一个'知道'都该打个问号。"

## 四、继续 scout、不重开新场景的原因

1. **时间与投资回报**。秋招这档期，重开一个代码 Agent 场景注定要重建语料、评测、消融、文档，
   最少 2-3 周才能打到 scout 现在的 70% 深度。
2. **题库分成分布**。82 题里设计判断类与 RAG 工程类占了近七成；那部分 scout 已经
   能给出**比标准答案更硬**的答案。高并发缺口那部分，**原项目（平台：异步入库 / 流式 /
   降级）正是救场的解法**。
3. **差异化密度**。有声实验（注入故障找 bug）、写负向消融表、公开基准真实对照——
   这些点大多源于一个"没结变现的项目"，不是相机这么好拍的，不加时间会重新长出来。

继续打磨。不要重开。
