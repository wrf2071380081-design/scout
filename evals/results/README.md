## v2 标注集（200 题）的实测

```bash
scout eval run --dataset evals/longdoc_v2_draft.json --corpus datasets/longdoc-gold \
  --out reports/v2.json --markdown evals/results/longdoc_v2_report.md
```

- Recall@5 **69.5%**（v1 的 94.7%）——生成的问题更接近真实分布，天然更难
- **误拒率 23.0%**（初期为 27.7%）——根因是自动生成的问题里混入了模板套话
  （「根据知识库回答」「量化目标或要求」），评分器被自己的 token 误伤；
  过滤模板停用词后回复该指标。见此轮排查 [`docs/FINDINGS.md`](../../docs/FINDINGS.md) 第六轮
- 作答率 **75.0%** / 拒答正确率 100% / 注入泄漏率 0%
- 200 条全跑完 ~**70 ms / 题**（离线启发式模型下），说明这套评测本身跑得起来

## pipeline 与 multiagent 的诚实对照

同一标注集（v2，200 题）、同一语料、同一启发式模型：

| 指标 | pipeline | multiagent | 变化 |
|---|---|---|---|
| Recall@5 | 69.5% | 67.5% | −2.0pp |
| MRR | 48.5% | 48.8% | +0.3pp |
| **作答率** | 75.0% | **79.0%** | **+4.0pp** |
| **误拒率** | 23.0% | **20.4%** | **−2.6pp** |
| 拒答正确率 | 100% | 100% | 持平 |

**诚实的结论**：

- 多智能体在这份语料上的真实收益是**减少了误拒**（上下文压缩让充分性门控
  更少误杀），不是提高了召回。
- 在 2-4 条真实多文档案例上**没有一致的收益**——样本太小，不足以得出结论。
- 它还暴露了一个真实代价：拆成子查询后按分数合并，
  会把单查询本来排得靠前的证据挤出 Top-5（`cross_doc_2027_targets` 1→0）。

> **多智能体不是免费的。** 它的价值是解决"上下文隔离"这个问题，
> 不是"多个人"本身。这是面试里比"我用了多智能体"强 10 倍的答案。

## 故障注入（自愈编排的量化证据）

`scripts/fault_injection.py` 在可预期的位置注入 8 类典型故障
（provider 超时、种类化异常、非法参数、重复调用死循环、未知工具、
checkpoint 状态损坏、JSONL 崩溃半截、HITL 审批超时），测量两条红线：

| 指标 | 结果 | 意义 |
|---|---|---|
| 类型化失败率 | **100%（8/8）** | 失败结束时是稳定的错误码，不是裸异常栈 |
| 预算内恢复率 | **100%（8/8）** | 重试 ≤ 预算后完成或体面降级 |
| 未捕获裸异常 | **0** | 崩溃逃逸为零 |

这个实验真正找到并修复了两处生产级 bug——包括 **decide 阶段 ProviderError 直接
穿透主调用栈**（平时没人见，因为只有在服务挂的瞬间才暴露）。
详细过程见 [`docs/FINDINGS.md`](../../docs/FINDINGS.md) 第七轮。

> v2 是**草稿**——其中一部分生成的问题关键词与原文贴合度不高，
> 是下一个迭代里该动手修（或删）的内容。保留它的价值恰恰在于：
> 有 23% 的识别失败是评测"有用"的证明，不再是"零短板的展示样例"。

## 重要提醒

- **样本量仅 19 条，上述百分比只具方向性，不构成统计结论。**
- 报告中的 `keyword_coverage` 偏低是离线实现（词法抽取拼答案）的固有短板，
  不代表检索或生成链路的真实能力上限。配置真实模型后需重新测量。
- 复现命令：

```bash
scout eval run --dataset evals/longdoc_v1.json --corpus datasets/longdoc-gold \
  --out reports/after_idf.json --markdown evals/results/after_idf.md
```
